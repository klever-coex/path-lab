# clover2-gym

Этот комплект позволяет разрабатывать и проверять решение задачи
о планировании полёта гоночного дрона в PyBullet.

## Установка

Установите [uv](https://docs.astral.sh/uv/getting-started/installation/).

Установите зависимости, включая `matplotlib` для PNG-отчётов:

```bash
uv sync --extra viz
```

## Примеры запуска

```bash
# Посмотреть трассу: номера ворот показывают порядок прохождения
uv run clover2gym viz --task tracks/primacy/rectangle.yaml

# Показать трассу вместе с планируемой траекторией
uv run clover2gym viz \
    --task tracks/primacy/rectangle.yaml --solution solutions/template_solution.py

# Проверить решение без симуляции
uv run clover2gym check \
    --task tracks/primacy/rectangle.yaml --solution solutions/template_solution.py

# Выполнить полный прогон без графического окна и сохранить отчёт
uv run clover2gym run \
    --task tracks/primacy/rectangle.yaml --solution solutions/template_solution.py \
    --out output/report.json --plot output/report.png

# Посмотреть полёт в GUI и вывести время прохождения ворот в журнал
uv run clover2gym -v run \
    --task tracks/primacy/rectangle.yaml --solution solutions/template_solution.py --gui

# Проверить все доступные трассы, включая вложенные каталоги
uv run clover2gym run-set --task-dir tracks/ --solution solutions/template_solution.py
```

## Что есть в комплекте

- [`solutions/template_solution.py`](solutions/template_solution.py) — стартовый
  пример: строит сплайн через точки перед воротами и после них. Это основа
  для доработки; успешный полёт на каждой трассе нужно проверять отдельно.
- [`tracks/primacy/`](tracks/primacy/) — публичные трассы для Первенства.
- [`tracks/championship/`](tracks/championship/) — публичные трассы для Чемпионата.
- [`clover2gym/`](clover2gym/) — исходный код формата задания, траектории,
  проверок, контроллера и симулятора.

## Работа с бейзлайном

Скопируйте `solutions/template_solution.py` и редактируйте копию. При запуске в 
командах выше замените путь после `--solution` на путь к вашей копии.

Бейзлайн строит маршрут по геометрии ворот, затем превращает его в траекторию
с помощью кубического сплайна. Функция `solve(task)` выполняет следующие шаги:

1. Добавляет стартовую позицию `task.start_pos` первой опорной точкой в `wps`.
2. Для каждых ворот из `task.gates` добавляет две точки:
   `g.center - g.normal * SHOULDER` перед воротами и
   `g.center + g.normal * SHOULDER` после них. Нормаль `g.normal` имеет
   единичную длину и указывает направление прохода, поэтому `SHOULDER`
   задаёт расстояние от центра ворот в метрах.
3. После всех ворот добавляет конечную точку
   `last.center + last.normal * 3.0` — в трёх метрах за последними воротами.
   Это оставляет участок для продолжения полёта и замедления после финиша.
4. Передаёт массив опорных точек в конструктор:

```python
Trajectory.from_waypoints(
    np.array(wps), dt=task.timing.dt_max, cruise_speed=SPEED
)
```

Например, для ворот с центром `[8, 0, 2]` и нормалью `[1, 0, 0]` при
`SHOULDER = 1.5` получатся точки `[6.5, 0, 2]` и `[9.5, 0, 2]`.
Они задают подход и выход вдоль нормали. Сам центр ворот в `wps` не добавляется.
Сплайн между точками изгибается под влиянием соседних участков, поэтому
такой выбор точек не гарантирует пересечения точно через центр проёма.

### Параметры бейзлайна

| Параметр | Значение в шаблоне | На что влияет |
| --- | --- | --- |
| `SPEED` | `3.0` м/с | Расчёт времени между опорными точками |
| `SHOULDER` | `1.5` м | Расположение точек перед каждыми воротами и после них |
| Отступ конечной точки | `3.0` м | Длину участка за последними воротами |
| `dt` | `task.timing.dt_max` | Шаг отсчётов возвращаемой траектории |

`SPEED` — ориентир для назначения времён, а не фиксированная скорость полёта
или её верхний предел. Без явного `times` конструктор рассчитывает времена
по длинам участков и `cruise_speed`, отводя больше времени на стартовый
и конечный участки для разгона и замедления. Фактическая скорость вдоль
сплайна меняется и может превышать `SPEED`.

`SHOULDER` меняет форму маршрута: больший отступ разносит точки подхода
и выхода, но при близких воротах или резких поворотах может создавать
неудобные переходы между ними. Отступ конечной точки отсчитывается от центра
последних ворот; он задан отдельно от `SHOULDER`.

Конструктор строит вспомогательный сплайн с нулевой скоростью на обоих концах,
берёт из него позиции через равные интервалы `dt` и возвращает `Trajectory`.
Уменьшение `dt` увеличивает число отсчётов, а не задаёт более быстрый полёт.
Чтобы самостоятельно распределять время между участками, передайте `times` —
массив времён посещения опорных точек, начиная с нуля. Его длина должна совпадать
с числом точек; после округления к сетке `dt` времена должны оставаться строго
возрастающими.

### Что можно улучшить

Бейзлайн использует одинаковые `SPEED` и `SHOULDER` для всех ворот. Он
не подбирает их по крутизне поворотов, размерам проёмов, границам арены
или возможностям контроллера и не проверяет результат внутри `solve()`.

Для начала можно менять скорость, выбирать отступы отдельно для каждых ворот
и задавать больше времени на сложные повороты через `times`. Следующий шаг —
подбирать точки прохода внутри проёмов и сглаживать переходы между воротами.

После изменения опорных точек или времён запускайте `check`, затем `run`.
Конструктор сам по себе не гарантирует успешного прохождения проверок,
а фиксированные три метра за финишем не гарантируют нужную длительность
продолжения траектории при любой выбранной скорости.

## Результаты и отладка

В GUI клавиша `f` переключает камеру слежения и свободную камеру.
Для запуска сразу со свободной камерой добавьте к `run --gui` опцию `--no-follow`.

В JSON-отчёте смотрите `passed`, `stage_failed`, `lap_time`, а также нарушения
и статистику в `static` и `sim`. На PNG зелёным показан план, красным —
фактический полёт, если симуляция запускалась. Команды `check` и `run`
возвращают код `0` при успехе и `1` при провале проверки.

Начните со статической проверки, затем проверяйте полный полёт. При промахах
сравнивайте план с фактической траекторией и оставляйте запас до рам:
увеличение скорости может ухудшить отслеживание.
